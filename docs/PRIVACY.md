# Private deposits with Helius Solana Privacy Rings

Status: **beta integration**. The UI, adapter, API proxy and demo flow are done. On real networks, private deposits
stay **disabled (fail closed)** until the program change in §5 ships. Research date: 2026-11-26.

## 1. The leak we are closing

A sealed bid is `commit_bid(commitment, deposit)`:

| Field | Where it lives | Visible during commit? |
|---|---|---|
| max price | inside `commitment = keccak256(bidder ‖ max_price ‖ bid_amount ‖ salt)` | no |
| bid amount | inside the commitment | no |
| **deposit** | public SPL `Transfer` bidder ATA → escrow PDA; also stored in plaintext as `SealedBid.deposit` | **yes** |

Because `bid_amount ≤ deposit` (checked in `reveal_bid`), the public deposit is an upper bound on bid size. Whales can
be spotted and copy-traded during the commit window. Refunds (`claim_or_refund`) and holder payouts also go to public
token accounts, so the amounts show there too.

## 2. What Helius Solana Privacy Rings provide (verified)

Sources: [overview](https://www.helius.dev/docs/privacy), [SDK](https://www.helius.dev/docs/privacy/sdk.md),
[RPC reference](https://www.helius.dev/docs/api-reference/privacy/llms.txt), [endpoints](https://www.helius.dev/docs/privacy/endpoints.md),
[addresses](https://www.helius.dev/docs/privacy/addresses.md), and the deposit, transfer, withdraw and read-balance guides.

- **Default (confidential) Ring**: encrypts the **amount and asset** of private balances and transfers (SOL, SPL, Token-2022).
  **Sender and recipient addresses stay visible.** Custom Rings (enterprise) can also hide the parties.
- **Keys**: a *shielded keypair* has an Ed25519 signing key, an X25519 **viewing key** and a nullifier key. The public
  *Shielded Address* is `(signing_pk, nullifier_pk, viewing_pk)`, published in a user-registry PDA. A wallet derives it
  from an Ed25519 signature over the off-chain message `"TSPP/derive/v1"`, followed by HKDF.
- **Flows** (TS SDK `@heliuslabs/spr`):
  - *deposit* (public → private): `depositInstruction({ tree, depositor, deposits: [{ asset: DepositAsset.sol() | DepositAsset.spl({...}), viewTag, recipientOwnerHash, amount }] })`.
    **The deposit is public: sender, recipient, asset and amount.** No ZK proof needed.
  - *confidential transfer* (private → private): `new ConfidentialTransfer(addr, inputs, payer).send(recipientShieldedAddress, mint, amount)` → `.sign()` → `client.proveTransact()` → `transactInstruction({...})`.
    Shows only sender and recipient. **The recipient must be a Shielded Address.**
  - *withdraw* (private → public): `ConfidentialTransfer#withdraw(mint, amount, WithdrawalTarget.sol|spl(...))` + `TransactWithdrawal`.
    **The amount is public.**
  - *read balance*: indexer `getShieldedTransactionsByTags` (the view tag is the owner's pubkey in confidential rings), then local `decryptToBalances({ keypair, registry, transactions })`.
- **Indexer JSON-RPC** (`https://{mainnet|devnet}.helius-rpc.com/v1/spr/{method}?api-key=…`): `getEncryptedUtxosByTags`,
  `getShieldedTransactionsByTags`, `getShieldedTransactionsBySignature`, `getShieldedTransactionsByNullifiers`,
  `getMerkleProofs`, `getNonInclusionProofs`, `getNullifierQueueElements`, `getUserRecords`.
- **Proofs**: generated by the Helius-hosted prover (inside a TEE, behind the RPC URL) or by a local prover (`zolana dev start` → `:3001`).
- **Programs** (same ids on mainnet and devnet): Solana Privacy Program `ring1GaLCuJnkUMVkX2JeZLTTX17wKsV4fZmPVzXANW`,
  User Registry `regy3WAeRXMYuMYxr5iK3Bf9Arr3PcxGxyzAddbiqDQ`, state tree `777pvSGe5LaBd9nCczvE2FXEauiwtfGJ5XRpjKyniGor`.
  Mainnet token interfaces exist for SOL, USDC, USDT, JitoSOL and JUP. Any other mint needs `getCreateSplInterfaceInstructionAsync` first.
- **Network availability: the docs disagree.** The overview page says "Beta, devnet only, mainnet has not launched". The
  endpoints and API-reference pages list mainnet beta URLs, and the Nov 10 2026 announcement says mainnet beta. We support
  both and probe liveness at runtime (`GET /api/privacy/status`).
- **npm**: `@heliuslabs/spr@0.9.0-alpha` was published 2026-11-04 and is co-maintained by `@helius.xyz` accounts. Its peer
  dependency is `@solana/kit ^8.3.0`, and it needs Node `^22.12 || >=24`. **We do not install it yet** (see §6).

Behaviour of `privateDeposit`:

| Deployment | What happens |
|---|---|
| Demo launch (`launch.isDemo`) | Simulated ring: top up the shielded balance if short, `fundEscrow` (models a confidential transfer into a shielded escrow), then the normal demo commit. `CommitResult.privatelyFunded = true` and `privacySignature = "simring…"`. No real funds. |

## 4. Trust model: what is and isn't hidden

| | Today (public deposit) | Demo / target design |
|---|---|---|
| Max price, bid size | hidden until reveal (commitment) | same |
| Deposit amount | **public** | hidden (ring ciphertext; only the bidder's viewing key, or a key they share, decrypts it) |
| Refunds, holder payouts | public | hidden (confidential transfer to the bidder's Shielded Address) |
| Bidder address, escrow address | public | **still public** (Default Ring hides amounts, not parties) |
| Aggregate escrow / clearing results | public | public (batched settlement, §5) |
| Buyback drips, protocol fees | public | **public by design** (transparency guarantees) |

Who you trust:
- **Helius indexer**: it sees only ciphertexts and view tags. It learns who interacts with the ring, not amounts.
- **Hosted prover**: it runs in a TEE. Proof inputs include private witness data, so you trust the TEE attestation. Use the local prover to avoid this.
- **Our API proxy**: it relays JSON-RPC and sees the same ciphertexts as Helius. It never sees viewing keys.
- **Viewing key**: anyone you share it with can read your balances (they cannot spend them).
- **After reveal**: `reveal_bid` publishes max price and bid amount, and clearing math is public. Ring privacy protects
  the *commit window* (when copy-trading happens) and refund/payout amounts. It does not hide your revealed bid.

## 5. On-chain escrow compatibility analysis and contracts plan (do not edit programs/ from this workstream)

**Can the current escrow PDA receive confidential transfers? No.**
1. `escrow` is a plain SPL `TokenAccount` (seeds `["escrow", launch]`, owner = launch PDA). Ring transfers move value
   between ring UTXOs owned by **Shielded Addresses**, not into SPL accounts ("Private transfers move balances only
   between private token accounts, not public token accounts").
2. Getting value from the ring into the escrow means a **withdrawal**, and withdrawals publish asset and amount. That puts
   back exactly the leak we want to remove, and the withdrawal sits next to `commit_bid`, in the same transaction or in
   a linkable one.
3. `commit_bid` stores `deposit` in plaintext in `SealedBid.deposit` and adds it to `launch.total_escrowed`.
4. A PDA cannot hold a Shielded Address itself. Registration needs the owner's signature over `"TSPP/derive/v1"` and an
   X25519 viewing secret, and a PDA has neither. No ring CPI or program-owned-UTXO API is documented for the Default Ring.
5. Token-2022 Confidential Transfer is a separate mechanism (ElGamal ciphertexts on Token-2022 accounts). USDC, wSOL and
   the tokenized stocks are not CT-enabled mints, so it is not available for our quote assets.

**Plan (three phases):**

*Phase A (no Helius dependency, shippable now): bucketed deposits.* Add `commit_bid_v2(commitment, bucket)`, where
`deposit = BUCKETS[bucket]` (for example 100 / 1k / 10k / 100k quote units). The commitment preimage keeps the exact `bid_amount`.
The deposit then leaks only a coarse bucket. Refund math is unchanged.

*Phase B (Default Ring, custodial escrow operator): ring-funded commits.*
- New account `ShieldedEscrowConfig { launch, operator_shielded_owner: Pubkey, attestor: Pubkey }`.
- New ix `commit_bid_shielded(commitment, deposit_commitment: [u8;32], ring_receipt: [u8;64])`:
  - no SPL transfer. `SealedBid { shielded: true, deposit: 0, deposit_commitment }`, where
    `deposit_commitment = keccak(deposit ‖ salt2)`.
  - The bidder makes a ring **confidential transfer** of the deposit to the launch's escrow-operator Shielded Address.
    `ring_receipt` is the ring tx signature, and an off-chain attestor (the relayer, ideally in a TEE) checks that the
    output decrypts to the committed deposit. It co-signs `commit_bid_shielded`, which the program verifies with an
    Ed25519 precompile on `(launch, bidder, deposit_commitment, ring_sig)`.
- `reveal_bid_shielded(max_price, bid_amount, salt, deposit, salt2)`: checks both preimages and sets `bid.deposit = deposit`.
  The deposit only becomes public at reveal, when the bid is public anyway.
- `settle_shielded_batch`: after clearing, the operator makes **one aggregate ring withdrawal** of `Σ filled amounts` into
  the public escrow. That withdrawal is public, but it is already implied by `totalRaised`. The program checks
  `escrow.amount >= Σ fills` before `graduate`.
- Refunds: the operator confidential-transfers `refund_i` to each bidder's Shielded Address. `claim_or_refund` gets a
  `shielded` branch that only mints tokens and marks `claimed`, plus an attestor-signed `refund_receipt`.
- Trust: the operator custodies ring deposits between commit and settle. Mitigations: a TEE operator, a time-locked
  public fallback where anyone can force `refund_all` via withdrawal after `revealEndTs + grace`, and a bonded attestor.

*Phase C (non-custodial, when Helius Custom Rings or ring CPI allow program-controlled UTXOs; enterprise, targeted Q4 2026):*
replace the operator with a launch-PDA-owned ring account. `commit_bid_shielded` CPIs into the Privacy Program to lock
the UTXO under `(launch PDA, commitment)`. `settle` CPIs a batched withdrawal, and refunds CPI confidential transfers.
No attestor and no custody.

Client changes for B and C are prepared: `PrivacyRingClient.fundEscrow()` is the single seam, and
`useSealedBid` has a marked `TODO(contracts)` where `commit_bid_shielded` gets built.

## 6. Why the SDK isn't installed yet (real vs simulated)

Real, working against Helius today:
- `GET /api/privacy/status`: live probe via `getUserRecords`.
- `POST /api/privacy/rpc`: proxy for the 8 documented indexer methods.
- `HeliusPrivacyRingClient.isRegistered`: `getUserRecords`.
- `HeliusPrivacyRingClient.encryptedBalance`: `getShieldedTransactionsByTags`, which counts encrypted outputs.

Simulated or not yet wired:
- Shield, confidential transfer, withdraw and viewing-key decryption need `@heliuslabs/spr` plus a shielded keypair.
  Browser wallets (wallet-adapter) do not expose the secret key that `ShieldedKeypair.fromKeypair` needs. The documented
  derivation (a signature over the `"TSPP/derive/v1"` off-chain message v0, then HKDF) has no documented wallet-adapter
  entry point in the TS SDK yet.
- Shipping these operations would also bring `@solana/kit@8` alongside `@solana/web3.js@1` into the web bundle.
- They therefore sit behind `HeliusSprBindings` and throw `PrivacySdkUnavailableError` with a doc link.
- To enable them: add `@heliuslabs/spr@0.9.0-alpha` (exact pin) to `packages/defi` and implement `HeliusSprBindings`
  with the SDK calls named in §2.
- Escrow funding fails closed on real networks until §5 ships.
